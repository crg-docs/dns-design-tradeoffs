# 第9章「後方互換性と発展性」の設計メモ

- 対象文書: [第9章](../../chapters/09-compatibility.md)
- 状態: 初稿公開、設計・出典・ビルド・リンク・390px/1280px表示を確認済み
- 記録種別: 執筆時の記録
- 最終更新: 2026-11-26

## 目的

一斉更新できない経路で、新機能を使う条件と失敗時に残す保証を判断できるようにします。

## 中心メッセージ

拡張を理解しない相手と共存する設計には、未知の値の扱い、能力通知、失敗を説明する応答、段階的な検証が必要です。

## 読者に渡すもの

新しいレコードの利用と配送、能力の通知と到達性、フォールバックと保証の低下を区別する視点です。

## この文書の責務

世界中の実装を一斉更新できない中で既存利用と発展を両立する要求を扱います。理解と配送、情報と通信、能力通知と到達性を分けた解決と、必須の保証を落とせない条件を評価します。

仕組みの詳細、規則、観測コマンドは[準備章](../../chapters/01-name-resolution.md#必要な説明を引く)へ集約します。本編には要件と解決の関係を追うために必要な説明と根拠を残します。

## 扱わないこと

DNSSECや暗号化の機能説明は準備章へ戻します。特定のバッファサイズを普遍的な推奨として固定しません。

## 採用した構成と理由

同時に更新できない制約から、配送と利用の分離、能力の通知、独立した移行、未対応の明示、保証を残す代替動作へ進みます。

## 見送った案

拡張機能の年表をもう一つ作る案は採りません。仕様の公表年は第1章に任せ、共存する設計を評価します。

## 未決事項と見直す条件

今回の章に通信障害の注入実験はありません。特定の機器の不具合を主張する場合は、製品・版・条件を固定した記録が必要です。

## 判断履歴

### 2026-11-26に更新した以前の責務と構成

以下は変更前の記録です。現在の責務と構成は上記を優先します。

未知のRR型、EDNS、IPv6のデータと輸送の分離、途中機器、フォールバック、段階導入を扱います。

全主体を更新できない問題から、配送の透明性、能力通知、経路の失敗、導入条件へ進めます。

### 個別の判断

- 2026-11-23: 未知のEDNSオプションを無視する規定と未対応版への応答を区別し、応答成功を新機能の利用成功とみなしません。任意の性能改善と必須の保護で、導入範囲と従来経路を残す判断が変わる比較を置きます。 目的と扱う範囲は維持しています。

- 2026-11-20: RFC 3597、6891、3596、8906を中心に、仕様上の許容と現実の到達性を分けます。

- 2026-11-23: 著者の方針変更に合わせ、章末の対比表を「この章のポイント」3点へ変更しました。目的・責務は維持し、本文で説明した判断と条件を短くまとめます。言い換える力を養う狙いは、共通の執筆方針として残します。

- 2026-11-26: 一斉更新できないDNSで何を分離すれば発展を続けられるかを主軸にし、レコード型・EDNS・IPv6の詳細を準備章へ移しました。仕組みの網羅を章の責務とせず、DNSへの要求から考慮すべき非機能要件と解決を追う構成へ戻しました。従来の機能説明をこの章が担うという記述は、この判断で更新します。
